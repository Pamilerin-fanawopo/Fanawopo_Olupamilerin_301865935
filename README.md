

# FinTrust Customer and Financial Records

**Student ID:** 301865935  
**Course:** MIT8103 – Advanced Database Systems

## Project Overview

This portfolio uses fictional records for FinTrust, a fintech platform designed to manage customer information, financial accounts, deposits, withdrawals, transfers and audit records.

The project explores relational database design, query processing and optimisation, transaction management, NoSQL databases, and distributed database concepts.

## Portfolio Activities

### Portfolio 1: Database Design and Modelling
[View Portfolio 1](portfolio-1-database-design/)

Designed a relational database using MySQL. This includes six related tables, an ER diagram, relational schema, primary and foreign keys, constraints and database normalisation. SQL scripts and screenshots provide evidence of the implementation and validation tests.

### Portfolio 2: Query Processing and Optimisation
[View Portfolio 2](portfolio-2-query-optimisation/)

Created and executed SQL queries to retrieve and analyse financial records. Explored indexing and compared query performance using execution plans and measured lookup times.

### Portfolio 3: Transactions and Concurrency
[View Portfolio 3](portfolio-3-transactions-concurrency/)

Explored transaction management using COMMIT, ROLLBACK and READ COMMITTED isolation. Used two database sessions to demonstrate concurrency behaviour and how row locking helps prevent lost updates.

### Portfolio 4: NoSQL and Advanced Data Models
[View Portfolio 4](portfolio-4-nosql/)

Created a MongoDB `activity_events` collection using sample event documents. Tested document insertion, queries and validation rules, including invalid dates and duplicate event IDs.

### Portfolio 5: Distributed and Cloud Database Exercise
[View Portfolio 5](portfolio-5-distributed-cloud/)

Explored a proposed distributed database architecture covering replication, primary elections, majority acknowledgement, secondary lag, sharding, availability and consistency. This portfolio uses a discussion-based approach rather than a live deployment.
